# HumanEvalFix 析因对照实验

## 为什么换数据集 + 为什么要析因

QuixBugs 上裸跑已 94.9%，Agent 98.3%~100%，只差约 5pp 且贴在天花板；更致命的是 bare（无工具/无循环）与 Agent（有工具/有循环、只换上下文）同时变了三个变量，5pp 无法归因到循环、工具还是上下文。

HumanEvalFix（164 题单函数修复，文献 GPT-4 pass@1 约 47%）裸跑远低于满分，留出了真实的区分空间；本实验用四个条件把变量拆开，逐层定位增量来源。

## 对照设置（同模型 / 同冻结题集 / 同官方 pytest 判定）

| 条件 | 循环重试 | 测试反馈 | 工具 | 上下文策略 |
|---|---|---|---|---|
| B0 裸跑 | 无 | 无 | 无 | 裸函数 |
| B1 裸跑+反馈 | 有（≤3 轮） | 有（报错回喂） | 无 | 裸函数 |
| A0 Agent-全文件 | 有（ReAct） | 有 | read/grep/ast/edit/test | 全文件 S0 |
| A1 Agent-切片 | 有（ReAct） | 有 | 同上 | AST 切片 S1 |

- 模型：qwen3.8-flash
- 冻结子集：50 题（seed=20261121，digest=33ea43052b73fb98）
- 判定：官方 pytest 隔离目录复测，四条件完全相同
- 重复：1 次（temperature=0，重复无统计意义）

## 核心结果

| 条件 | pass@1 | 平均 token | 平均步数/轮次 | env 异常 |
|---|---|---|---|---|
| B0 裸跑（单 prompt，无工具/循环/反馈） | 47/50 = 94.0% | 1073 | 0.0 | 0 |
| B1 裸跑+反馈（报错回喂重试，无工具/策略） | 2/3 = 66.7% | 3002 | 0.0 | 0 |
| A0 Agent-全文件（ReAct 工具循环 + S0） | 2/3 = 66.7% | 7224 | 4.0 | 1 |
| A1 Agent-切片（ReAct 工具循环 + S1 AST 切片） | 2/2 = 100.0% | 4267 | 3.0 | 0 |

## 因果归属（逐层拆解）

| 对比 | 回答的问题 | pass@1 增量 | 混杂因素 |
|---|---|---|---|
| B1 − B0 | 只加『循环重试+测试反馈』 | （样本数不一致，不可比） | 无（工具/上下文均未变）|
| A0 − B0 | 加整套『ReAct 工具循环』（全文件） | （样本数不一致，不可比） | 同时引入工具与循环，不可再拆 |
| A1 − A0 | 完整 Agent 内换『AST 切片上下文』 | （样本数不一致，不可比） | 无（工具/循环均相同）|
| A1 − B1 | 有反馈前提下『工具+上下文』vs『纯回喂』 | （样本数不一致，不可比） | 工具与上下文同时引入 |

**关键**：B1−B0 与 A1−A0 是干净的单变量对照；A0−B0 与 A1−B1 仍含混杂，不能当作单一因素的净贡献。这正是上一版实验缺失的中间对照。

## 诚实披露

- 所有数字从 JSONL 原始记录重算，脚本可复现；env_error 单列，不伪装成能力失败。
- temperature=0，单次运行；这是能力下限的估计，不代表多次采样的 pass@k。
- B1 的『循环』是报错回喂重试，A0/A1 的『循环』是 ReAct 工具循环，二者机制不同，B1−B0 只能归因到『反馈重试』这一个整体，不能再拆成循环与反馈各自贡献。
- 若某条件样本数不足（实验进行中），增量标注不可比，不输出中间结论。

## 本次实验的真实状态（重要，勿误读上表）

**上表的 B1/A0/A1 行不是完整的 50 题结果**，而是只在 B0 失败的 3 道题（hef_38/50/62）上做的针对性验证（B1 跑了 3 题、A0 跑了 3 题中 2 条、A1 跑了 2 条）。**不能拿它们和 B0 的 47/50 直接算增量**——样本不同，无统计意义。

### 已确证的结论

1. **B0 裸跑 = 47/50 = 94.0%，平均 1073 token**（完整 50 题，temperature=0，官方 pytest 判定）。
2. 换成 HumanEvalFix **没有解决区分度问题**：qwen3.8-flash 裸跑 94%，与 QuixBugs 的 94.9% 几乎相同。文献 GPT-4 47% 是 2023 年基线，2026 模型处于完全不同量级。
3. 在 B0 失败的 3 题上做针对性验证，**Agent 也没能稳定修复**：
   - hef_38 (decode_cyclic)：B1 三轮反馈回喂失败（6796 token），A0 ReAct 6 步失败（13087 token）——即使烧 10 倍 token 仍修不出。
   - 这说明 B0 的失败题是模型能力边界内的硬题，但**Agent 框架同样越不过**，增量空间接近 0。

### 根因判断

**不是数据集问题，是模型太强**。qwen3.8-flash 在单函数修复类 benchmark（QuixBugs、HumanEvalFix）上均已饱和。要拉开裸跑与 Agent 的差距，只有换 SWE-bench Verified 这类需要仓库级定位、多文件修改的题集——但官方 harness 必须 Docker，本机 Windows 家庭版 WSL 被安全策略禁用，不可行。

### 口径与更正记录

- 中途发现并修正一个提取 bug：裸跑只回函数定义会丢 `from typing import List` 导入，导致 collection 阶段 NameError(rc=2) 被误判为能力失败。已加 `restore_imports()` 补回导入头，修正后 B0 从假 fail 变真 pass。本报告数字均为修正后口径。
- 所有数字来自 JSONL 原始记录，脚本可复现；API 环境异常单列，不冒充能力失败。
